# Interview Deck Outline

Date: 2026-04-09  
Purpose: define the final structure, timing, and narrative arc for a 10-12 minute interview deck

## Deck Goal

Present a coherent professional progression:

- operations-grounded problem solver
- KPI-driven analyst
- BI and platform lead
- Fabric-oriented analytics engineer with a governed proof of method

The portfolio project should land as the capstone of earlier real work, not as a disconnected side project.

## Audience and Style

- primary audience: mixed interview panel
- language: English
- tone: business-first, practical, technically credible
- technical depth: light on the main path, deeper only where it helps role fit
- visual direction: clean, understated, interview-safe, not salesy

## Core Narrative

Use this sentence as the deck thesis:

> I started by learning operations from the ground up, then turned repeated blockers and fragmented logic into analytical tools, then formalized that work into governed BI and Microsoft Fabric delivery.

Use this sentence as the deck close:

> The platform is changing from Azure and SQL toward Fabric, but the core problem is familiar to me: translate messy operational logic into governed analytical layers people can trust and use.

## Slide Sequence

### Slide 1: Title and professional identity

Open with:

- who you are
- what class of problems you solve
- why this deck is chronological

Best framing:

`Analytics Engineer / BI Lead turning fragmented operational logic into governed decision-support systems.`

### Slide 2: Career arc timeline

Show the five-phase progression:

- 2018-2021 operations foundation
- 2019-2021 overlap into KPI support
- 2021-2022 formal analyst phase
- 2022-2025 BI and platform modernization
- 2025-2026 Fabric portfolio proof

### Slide 3: Operations foundation and early process improvement

Emphasize:

- assembly-line work
- process improvement mindset
- QC trust
- learning the business from the floor

Main point:

- your later analytics work was credible because you understood the process before you modeled it

### Slide 4: Early analytics tooling across operations and customer-facing work

Emphasize:

- Excel-based supply chain and logistics tools
- order and inventory support
- collections work with uninterrupted supply
- weekly sales reporting
- 30+ customer support exposure

Main point:

- you were already doing decision support before your title caught up

### Slide 5: Formal analyst phase and business-rule tooling

Emphasize:

- KPI-led work
- SAP BusinessByDesign CSV extraction
- demand planning and allocation logic
- commission and rebate standardization
- integrated planning logic

Main point:

- you moved from reporting summaries to codifying business rules

### Slide 6: BI modernization and governance direction

Emphasize:

- Power BI Service
- dataflows
- SharePoint Lists, Power Automate, and Power Apps / Power Fx app delivery
- semantic consistency
- workspace separation
- documentation and standards
- customer-data governance and Azure direction

Main point:

- you were not only building reports; you were future-proofing the analytical environment

### Slide 7: Fabric portfolio proof

Emphasize:

- repo governance plane
- Fabric execution plane
- Bronze, Silver, Gold
- runtime governance
- semantic model
- report shell
- public-safe case-study surface

Main point:

- this project formalizes your way of working into a governed, explainable proof

### Slide 8: Why you fit this employer

Emphasize:

- same class of problem, new platform emphasis
- ability to translate legacy logic into governed layers
- comfort bridging business, BI, and platform work
- strong fit for a young data culture still formalizing definitions and delivery patterns

Main point:

- this role is a natural continuation of the work you have already been doing

## Appendix Use

### Slide 9: Tooling stack by era

Use when they want concrete platforms, tools, and implementation language.

### Slide 10: Current vs target Fabric architecture

Use when they want to probe architectural honesty, current-state vs target-state thinking, or medallion responsibilities.

## Claims Guardrails

Use these phrases:

- bounded proof
- governed package
- repo governance plane
- Fabric execution plane
- public-safe analytical case
- semantic model and report shell
- current implemented state
- target state

Avoid these phrases unless heavily qualified:

- enterprise Fabric administration
- full production finance platform
- live real-time operational cockpit
- Fabric already does everything
- full people-management story beyond what you can support
